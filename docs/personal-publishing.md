# Eagleye 个人创作

这条流程把阅读时的选择和批注，接到公众号文章与小红书图文草稿。内容由本人选材、修改和确认；生成与导出都不会向公域账号发送内容。

## 使用入口

1. 在首页或顶栏打开「编辑模式」。信息卡片出现「选入本次稿件」「我的看法」和可选的原文摘录。
2. 留下自己的理解、兴趣或审美判断。批注自动保存；保存失败会显示错误和重试入口。批注和收藏彼此独立。
3. 勾选一条或多条卡片。可以跨页面、跨日期组合，每篇最多 20 条。底部工具栏显示已选数量。
4. 点击「组合成稿」，或进入导航中的「创作」（`/publishing`）。调整素材顺序、批注、摘录和整篇想说的话。
5. 点击「一键生成两份图文稿」。页面会显示写稿和配图进度，刷新后可从草稿列表继续查看。生成完成时，公众号文章已插入配图，小红书首图已带同一张插图，其他图卡可各自配图。
6. 在「配图」区生成新插图、挑选原文图片，或上传自己的图片。写稿失败可用保存的素材重试，配图失败可保留文字并单独重试配图。已有草稿也可以直接补图。每篇最多12张，每张上传文件不超过8 MB。
7. 修改公众号和小红书的文字。在公众号配图上直接换图，或修改图片位置和说明。小红书可逐张选图，选择完整显示或铺满图框。保存后预览。
8. 下载公众号图文包（HTML、Markdown 和实际图片），或小红书 PNG 图片包和配套文案。图片保存在 Eagleye 中，导出不依赖外部图片链接。平台可能过滤粘贴图片，可从图文包上传图片；纯文字和富文本复制仍可使用。

选择会保存在当前账号的工作区，草稿保存生成时的素材与批注快照。之后修改卡片批注不会悄悄改变以前的草稿。

卡片批注会自动保存；成稿和写作偏好需要点击保存，生成与导出前也会保存相应内容。尚未提交的成稿修改会在同一浏览器标签页内暂存，切换站内页面后仍可返回继续编辑；刷新或关闭标签页前应先保存。

一条素材也可以生成短篇。小红书图卡按信息量生成1至6张，每张标题最多40字、正文最多200字，可以添加、移除和上移。图卡内容太多或空行太多时，会提示缩短或拆分，而不裁掉正文。

## 本人的风格

创作页可编辑写作偏好和本人的文字样本。可以从少量真实批注开始，不需要先准备大量文章。

「我的写作偏好」里的「行文风格」可切换到「葬AI · 锐评观察」。选定后保存偏好，或直接生成新稿。该风格把一个反常细节发展成有证据的判断，仍以你的批注和明确偏好为准。已经保存的草稿可以继续编辑。[样本分析与组件取舍](personal-publishing-styles.md)

只有主动将成稿收录为风格样本，才会把它加入后续写作参考。未确认的 AI 初稿不会自动成为本人的文风。

来源内容、批注和样本有不同用途：来源支撑事实，批注提供本人的判断，样本提供表达节奏。样本中的经历不得搬进新文章。缺少正文的条目会提示证据不足，不能写成亲测、已验证或确定的因果结论。

## 组件与运行

- 写作规则：仓库内固定快照的 `op7418/Humanizer-zh`，以及 `shir-danishyar/humanize` 的文风校准方法。许可与来源在 `vendor/publishing/`，各文件的上游 Git blob SHA 记录在 `manifest.json`。
- 文案模型：默认沿用 Eagleye 的 LLM provider/pool。可用 `EAGLEYE_PUBLISHING_TEXT_MODEL` 为创作指定现有网关的文本模型，沿用 `LLM_*` / `OPENAI_*` 的基址与密钥。
- 公众号排版：`markdown-it`、`sanitize-html`、`juice`。
- 图片处理：`sharp` 识别、旋转、缩放并重新编码上传和导入图片；`cheerio` 从所选原文提取候选图片；`ipaddr.js` 用于公网地址校验。原文不能公开读取或没有图片时显示说明，可以改用上传或生成。
- AI 插图：复用现有网关的 OpenAI 兼容 Images API。设置 `EAGLEYE_PUBLISHING_IMAGE_MODEL` 为网关实际支持的图像模型；基址和密钥默认沿用 `LLM_*` / `OPENAI_*`，也可通过 `EAGLEYE_PUBLISHING_IMAGE_BASE_URL`、`EAGLEYE_PUBLISHING_IMAGE_API_KEY` 单独配置。凭据只保留在服务端，未配置时上传与原文图片仍可用。
- 小红书图卡：`@resvg/resvg-js` 将图片和文字共同排版生成 PNG，`jszip` 打包。AI 插图有明确标识，原文图片保留来源，配图不作为事实证据。
- 中文字体与主题细节见 [组件说明](personal-publishing-components.md)。

安装使用仓库原有 Node.js 要求（Node 22.21+ 或 24.5+）和 `npm ci`。服务启动时会应用新增数据库迁移。启动命令仍为 `node server.js <port>`；数据库路径沿用 `EAGLEYE_DB_PATH`。

开发分支不能直接对正在运行的生产数据库启动第二个完整服务：Eagleye 启动会恢复任务并启用原有后台服务。运行与部署沿用 [ThinkPad 操作说明](../deploy/thinkpad/README.md)，检查后台任务结束后再切换正式服务。生产入口为站内「创作」（`/publishing`）。

## 独立体验入口

个人验收使用 `EAGLEYE_PUBLISHING_PREVIEW=1`，并将 `EAGLEYE_DB_PATH` 指向通过仓库在线备份工具取得的真实数据副本。必须先准备好副本，不能指向生产数据库。用不同端口启动，复用原有模型配置所需的环境变量，不复制支付或邮件凭据。

体验模式保留账号登录、阅读、选材、批注、成稿及导出；关闭启动时的采集、任务恢复、调度和支付回调队列处理。除阅读标记、收藏和个人创作外，其余写接口不开放。页面会显示体验版标识，登录使用独立 Cookie，避免与同一主机的正式站点互相覆盖。

体验版沿用快照时的账号与素材。批注、选择和草稿持久保存在体验数据库，后续重启仍会保留；正式站点的新素材不会自动同步进来。体验结束后的草稿迁移应单独处理，不能用体验数据库覆盖生产数据库。

体验服务使用独立的 systemd 用户单元和端口，实际地址由私有部署配置提供。数据与仅本机可读的运行配置放在代码仓库外。查看状态或停止体验时只操作该独立单元。

## 输出边界

公众号输出为可编辑文章、内联样式 HTML 和 Markdown。小红书输出为文案和 PNG 图卡 ZIP。外部账号授权、平台草稿箱上传与直接发布不属于此轮接口；可以用平台后台完成发布。

真实素材的观点、文风和版式由使用者验收。语法、依赖加载和基础接口检查不代表内容已通过验收。

交付检查限于变更文件的语法与静态检查、依赖加载、字体可用性、服务启动和必要功能连通。体验入口使用真实数据副本，由本人选择素材并验收生成、复制和图卡版式效果；不以模拟内容代替验收。正式部署按已授权的上线流程，在备份完成且采集任务空闲后应用新增迁移。
