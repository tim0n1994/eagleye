# Eagleye 1.1：持续更新的可信个人雷达

日期：2026-09-09。状态：实现完成，本地发布候选验收通过；未公开部署。承接 2026-09-08 可信雷达迭代，保留所有现有工作树改动。

## 1. 产品目标与本轮边界

让用户每天能看到新信息，将有限的阅读时间花在值得进一步研究的条目上，并知道摘要、排序和报告由什么证据及模型产生。1.1 的交付不是多配五个 URL，而是可控地利用多个模型处理真实积压、保持前台可用、失败可见且可以恢复。

本轮保留 Node/SQLite/Python、原生 ES modules、现有身份系统、来源顺序与三列来源布局。实现完整端点池、任务路由、真实模型归属、受控增量处理、管理员操作边界、恢复能力和发布验收。不开新云服务，不重写全站，不把五条同网关路由宣传为五倍吞吐，不将哈希向量视作语义质量。

## 3. 用户流程与验收体验

### 配置与诊断

管理员在设置页一次粘贴五端点块 → 预览每条完整 URL、协议、模型 → 分别探活 → 保存启用池。修改并发/任务范围时保持现有密钥，不把打码占位符覆盖真密钥。普通用户不获得密钥、不能触发探活或修改系统任务。

每个端点展示启用状态、任务范围、并发上限、当前运行/等待、最近成功/失败与延迟样本；展示网关全局上限。未知/未测单列，探活成功不称为业务质量通过。密钥只在本地运行配置中存储，不进入源码、PRD、日志或指标。

### 阅读与研究

首页展示真实最新数据日期；信号筛选和详情继续保持上一轮可信表达。新摘要和研究报告保存实际执行端点、请求/返回模型及必要的 trace。模型调用失败不生成空的成功报告；正文来自已有条目证据，对未取得原文或无法证实的内容明确保留不确定性。

### 管理员增量更新

启动有范围/批量上限的更新任务 → 可查看每阶段产出、失败原因 → 可取消 → 再运行不删除有效历史结果。源抓取、富集、评分、KG、简报形成可验收的链条。重启对中断任务给出明确终态，不永久阻塞后续调度，也不未经约束回放付费调用。

## 4. 技术架构与接口契约

### 4.1 端点池

沿用 user_data 配置存储，新增 llm_pool_config，schema_version=1。配置字段：enabled、global_concurrency、queue_limit、request_timeout_ms、queue_timeout_ms、max_attempts，以及 endpoints 数组。每项含 id、label、protocol、endpoint_url、api_key、model、enabled、concurrency、tasks。协议与模型名独立；endpoint_url 是完整请求地址，必须原样保留 /v1/messages-2 等路径。

默认保守全局并发 5、每路 1，完成吞吐对照才调高。任务类型：enrich、classify、translate、digest、research、graph、general；所有既有 getProvider/getEnrichProvider 调用进入同一个进程级池，避免每次构造新池导致并发限制失效。未启用池时保持旧单端点兼容；启用后全部不可用应明确失败，不暗中绕到未配置的旧端点。

传输仅发送用户提供的本地路由；HTTP 错误、空响应、超时、截断和无效 JSON 可区分。支持请求总时限与取消，确保异常始终释放槽位。2 次最多不同端点尝试，避免与调用方旧重试叠乘；连续临时失败短暂熔断，半开单请求探测。队列有上限/等待时限，交互任务可优先但必须防止后台永久饥饿。HTTP 401/403 不盲目重试同路。

保留 provider.call(prompt, options) → string 接口，增加 callWithMetadata → {text, metadata}，metadata 含 endpoint_id、protocol、requested_model、model（实际返回优先）、latency_ms、usage、attempts、trace_id。并发归属禁止通过共享 lastModel 属性传递。options 支持 task、signal、json、validate（纯输出校验）；校验失败可受统一尝试预算约束转其他路。

### 4.2 管理 API

以下 API 全部 admin-only，错误采用已有 JSON error 形状。

- GET /api/settings/llm/pool → {status, config（密钥打码）, runtime, metrics}。
- PUT /api/settings/llm/pool，body {config} → 验证后持久化并热更新；密钥缺省或打码时按 id 复用旧值，新 id 必须提供密钥。
- POST /api/settings/llm/pool/parse，body {pasted} → {status, config}；只解析，不写入，不回传明文密钥（保存使用原粘贴文本或保留客户端已输入值）。PUT 可接受 {pasted, enabled:true}。
- POST /api/settings/llm/pool/test，body {endpoint_id} → 最小协议探活结果；只测试已保存配置，不由普通用户自由指定请求地址。深度业务/吞吐测试作为明确验收脚本独立执行。
- 持久化 llm_request_events：trace/attempt/endpoint/task/status/error_code/elapsed/tokens/time；不存 prompt、原始响应或凭据。运行时状态注明进程内，重启后指标仍可查。

### 4.3 业务输出与流水线

摘要、分类、翻译、简报、研究、图谱带明确 task；摘要和研究使用调用返回 metadata 持久化实际模型。JSON 至少验证输出形状、必要非空字段、请求 item_id 完整性；批次缺项只对缺项补偿。富集完成后按实际成功 item IDs 评分，不能以成功数量切出错误前缀。

系统 mutation 必须指定 POST/PUT/DELETE 且 admin-only。旧全量 reenrich 不能先清空有效内容；废弃危险默认行为并给出安全增量替代路径。研究读取 GET 不触发生成，生成使用 POST 并保留现有用户可用性与明确失败状态。

## 7. 实施决策与最终结果

按上述范围直接实施，无需逐项等待设计确认。预算由每个任务批量、最大尝试、最大 token 和超时约束，不运行无界全库 LLM 回填。最终结果与后续决策如下。

已交付：五路统一池、管理员配置、实际响应归属、有限批量更新、取消/重启恢复、原子迁移、桌面及窄屏设置交互。全局并发保持 5、单路 1；没有足够的长期任务质量证据支持硬编码“某模型一定负责某任务”，因此默认五路适用于所有任务，管理员可依据实际指标收窄任务范围。相同 10 条样本两组均成功，单路 118.287 秒、池 16.162 秒；单次约 7.3 倍吞吐仅为此实验结果。

真实验收追加并完成两条内容契约：无正文或正文重复标题时，生成明确未核验的来源标题卡片，不消费摘要模型、不产生 AI 标签；条目研究只使用存储原始材料，服务端核对每条引文为对应材料的真实子串，将解释标为假设。短描述不强行扩成长报告。研究页展示摘要实际模型和未独立核验提示。

全部 G1–G8 在限定本地候选范围通过，542 项 JS 与 11 项 Python 回归通过。完整证据及未验证边界见 [验收记录](releases/2026-09-09/ACCEPTANCE.md)，启动、备份、回退与性能复现见 [运行手册](releases/2026-09-09/RUNBOOK.md)。原数据库和 WAL 不变；试跑服务使用独立副本并只监听 127.0.0.1:3029。

后续迭代触发条件：先积累各任务的成功率、耗时和人工质量反馈，再决定按任务分工或调整并发；确认真实投递和部署环境后才开启持续调度。语义模型升级与全量历史修复需要独立样本评估，不能由本轮有限成功样本直接推断收益。
