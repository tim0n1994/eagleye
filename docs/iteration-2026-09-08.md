## 目标回顾与决策

原始目标是信息源聚合、可追溯 AI 理解、研究行动和可探索知识图谱；随后发展为通过 Alpha 排序、三类读者视角、收藏与订阅降低信息过载的个人雷达。保留 Node/SQLite/Python 与原生 ES modules。六月、七月的实现记录有价值，但历史计数与 HTTP 200 不能证明当前产品闭环。

最近提交已完成静态压缩、五库按需加载、路由清理、焦点/标题/live region，以及 formatter 生产实现测试。PROGRESS.md B70 的相关待办已过时，本轮不重复实施。

本轮选择先让雷达可持续处理所有源，并如实表达数据和证据状态。新增模型、大规模图谱迁移、更多信息源和工具都依赖这层可信基线，放到后续。

## 模块边界与并行实施

1. **KG 增量与主题保全**：Python worker 的默认源覆盖所有活跃源；缺失/变化内容优先且有源间公平性；向量按目标模型实际缺口选取；重复有限批处理推进积压。局部主题重建只替换本次范围内关联，事务失败保留旧图，其他源不受影响。Node 调用使用同一源范围和明确批量限制。
2. **流水线结果契约**：阶段失败必须反映到最终结果；保留具体失败、降级与取消信息，不能以 completed:true 掩盖。取消后的结果仍是可解析 JSON。全流水线去掉六源硬编码。
3. **质量读模型与界面**：通过已有 system/stats 提供真实摘要成功/可重试/耗尽分区、最新数据日期与过期状态、KG 覆盖；首页与设置明确展示历史数据/未知状态。率以实际成功记录为分子，空库不显示虚假 100%。
4. **雷达操作与证据含义**：用统一 URLSearchParams 构造筛选，类型/读者/时间范围互相保留；没有今日数据时不推断“今日下降”。跨源验证只由与该条目确有关系的来源构成。For-You 的 Alpha 显示为排序分而非置信概率。
5. **隔离验收**：提供显式 DB 路径配置，Node 与 Python 使用一致路径。验证数据库和本地验收实例与原库隔离；不触发真实采集、付费 LLM 或大规模原库回填。原库通过只读检查保留。

## 验收标准

- 小批量重复运行推进至少三个源的缺口；已完成项不占用新批额；新增/变化内容能重新处理。
- 在两个源已有动态主题时，仅重跑一源或模拟失败，另一源与此前有效图不丢失。
- 成功、局部失败、全失败、取消均有一致的持久化终态与阶段详情。
- 100 条、30 摘要、10 可重试、60 耗尽的测试库，显示已富集 30%，不能显示 90%。
- 旧数据明确标记历史日期；今日无样本不显示上升/下降；空库和 API 故障表达未知/无数据。
- 类型 × 读者 × 时间范围组合链接可实际导航与刷新，筛选不丢失。
- 无关来源不增加 cross_source_score；有关来源增加且能复算；Alpha 不冒充概率。
- JS、Python 回归、lint、原生浏览器模块与实际页面操作均记录；既有失败单列。
