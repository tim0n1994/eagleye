# 「葬AI · 锐评观察」的写法

这个预设借鉴葬AI几位作者共有的叙事方法。它从一个具体细节切进去，选一把读者能理解的尺子，从证据里写出判断。适用于产品试用、行业观察、技术比较，也适用于别的领域里值得多问一句的小发现。

## 样本怎么读

从 [葬AI文章索引](https://funeralai.cc/articles/) 选了七篇完整评论和两篇含来稿的编者部分，覆盖不同作者、主题和篇幅。译文、来稿和网页页脚不计入风格提炼。以下是阅读时记录的叙事动作，文章链接用于回查。

| 样本 | 叙事动作 | 在 Eagleye 里的用法 |
| --- | --- | --- |
| [Tripo最会打小人](https://funeralai.cc/articles/164/) | 续费经历先交代作者为什么关注，随后用打印、发声和游戏动画逐层测试。换了用途，优劣会互换。 | 比较前先交代同一个任务。把「好不好」拆成可观察的使用边界。 |
| [豆包手机纯属豆姐痛机](https://funeralai.cc/articles/160/) | 开头先修正此前判断，再用外卖任务的实际耗时和接管次数说明为什么「可以做」仍可能不值得做。 | 让新证据改写开头的预期。明确费用、时间和操作成本从哪里得出。 |
| [开源模型亟需另开一桌](https://funeralai.cc/articles/162/) | 从榜单成绩与使用感的反差追到谁有权定义模型能力，最后给出按实际任务评估的主张。 | 遇上排名，追问指标奖励了哪种行为、漏了什么。把解释与动机推测分开。 |
| [大模型需要雷军](https://funeralai.cc/articles/150/) | 车载帐篷先作为一个想买车的具体理由，再成为观察模型产品定义的视角，最后回到开头的车。 | 可以跨领域类比，但只迁移一层说得清的关系。用回扣给长文收尾。 |
| [个人主义才能救AI](https://funeralai.cc/articles/154/) | 把生产力的抽象承诺落到一个白领的工作日，再问节约的时间归谁。 | 把抽象能力翻成某个人的具体得失。观点的力度来自观察和批注。 |
| [客观评价字节阿里腾讯之Agent大战](https://funeralai.cc/articles/144/) | 用几家公司的产品动作开场，沿入口、组织协作和现金流解释差别，文中交代个人观察的边界。 | 多条卡片围绕一个问题对读。把组织或商业解释写成有依据、可修正的判断。 |
| [我妈不让我和百度搭子玩](https://funeralai.cc/articles/146/) | 先聊竞争宣传，再用录音整理等任务验证宣传，最后把产品表现放回竞争进程。 | 允许一个小产品提供有价值的参照。用任务结果承接笑点。 |
| [伊朗闭门造AI](https://funeralai.cc/articles/161/) 编者部分 | 现场见闻先改变刻板预期，再用服务可用性和创业者访谈补足限制，有疑问就留着。 | 有现场素材时，从日常动作进入宏观问题。保留实际观察与推测之间的距离。 |
| [Manus团队测模型一点微小的经验](https://funeralai.cc/articles/143/) 编者部分 | 由一条讨论起笔，引向「如何判断文字易读」这个小问题，再把话头交给真正做评测的人。 | 引用别人亲历时保留归属。指标和比喻都要服务读者正在追的那个问题。 |

七篇完整样本按网页正文的空行粗略分段，单篇段落长度中位数约为 42–53 个字符。这个数字含少量图注，只用于说明节奏。段落短的同时，作者也会用较长的段落讲完一个操作过程，再用一句短话落下态度。不同作者的俏皮程度、常用词和结尾方式差别较大，因此预设保留长短交替和证据后的轻微反讽，不把个人口头禅写成规则。

## 怎样落到生成

- 先从所选卡片里找一个能撑住全文的问题。产品实测更适合沿任务推进，行业观察更适合对照指标与用途，现场材料更适合由细节放大。资料薄时写清一个点就够了。
- 所选素材和摘录限定事实范围，批注与本次想说的话提供作者判断。可选风格提供叙事安排，用户自己的样本和偏好继续决定表达。参考文章的事实、经历与措辞留在原文。
- 公众号可以展开原因、反例和转折。小红书用首图给出一个细节，后面的图卡逐步添证据，最后落到读者能理解的一次选择或一个具体问题。
- 用同一组选材和批注对照两篇实际新稿时，主要看开头能否说出一个值得追的问题、每段有没有改变读者的理解、判断能否找到证据、读完是否还记得开头的那个细节。两个平台的叙事分别判断。

## 开源方法取舍

| 组件 | 在这版里的作用 |
| --- | --- |
| [humanize](https://github.com/shir-danishyar/humanize/blob/main/references/voice.md)（MIT） | 复用现有的语气校准规则，借用句段节奏、转折习惯与语域的观察维度。 |
| [Humanizer-zh](https://github.com/op7418/Humanizer-zh)（MIT） | 复用已有中文编辑规则，校对套话、虚张声势和多余总结。 |
| [Write Like Me](https://github.com/marcusnelson/write-like-me-claude-skill)（MIT） | 对照其从多篇样本归纳证据、关注起笔和收尾的方法。Eagleye 仍使用现有 Node 流程。 |
| [DSPy](https://github.com/stanfordnlp/dspy)（MIT） | 其 few-shot 方法适合已有「素材与批注 → 用户认可的稿子」样本后校准选例。当前选用可人工审阅的规则预设，避免引入额外的模型调用和评测依赖。 |

预设文本在 `server/services/publishing-styles.js`。新选项通过既有 `publishing_voice` 保存，分享和导出使用草稿本身。
