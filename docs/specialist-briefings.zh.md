# 具身 AI 与 AI 教育专题

## 设计依据

Eagleye 原有采集器、去重、翻译、来源记录和论文元数据是两个专题的共同底座。参考资料为用户提供的 `rea-orangebot-analysis.zip`，其中 `PROTOCOL.md` 描述了 OrangeBot 的每日来源快照 API、日期参数、预渲染和信息分发；另结合仓库内 `architecture-design.md` 以及 OrangeBot 的公开 Physical AI 页面。

| 方面 | OrangeBot 参考分析 | Eagleye 的取舍 |
| --- | --- | --- |
| 页面与存储 | Next.js 预渲染、Firestore 每日文档 | 保留现有静态前端、SQLite 和可追溯的逐条记录，不为专题更换技术栈 |
| 发现与回看 | 按信息源及日期查询快照 | 复用 `digest_date` 和来源明细，增加具身 AI 日期筛选 |
| 摘要 | 样本中有未经清理的 LLM 原始文本 | 延续结构化富化，标明 AI 摘要与原文摘要，保留原文链接 |
| 访问和增长 | 部分来源 API 公开，依赖爬虫索引 | 保留既有登录和 API 授权；公开 SEO 需要独立确定产品与访问策略 |

OrangeBot 的专题把论文、公司动态与监管申报分流，并为每条内容保留原文入口；分析还展示了其按日期查看各来源快照的模式。Eagleye 原来的页面只显示三个来源、按通用评分取数、写死同步频率，并遗漏已实现的 SEC 采集器。现在专题使用实际来源和发布时间，排除已标记的重复项和公司占位记录，展示 SEC 分区，并可按采集日期回看；生成摘要与原文摘要分别标注。采集、翻译和证据存储仍复用 Eagleye 自己的链路，登录保护也保持现状。

## AI 教育

新专题从已有语料中筛选同时涉及 AI 和教育的内容，按教学实践、学习产品、研究、政策组织，保留来源和原文。候选召回要求标题含教育线索，以减少大学机构名称、模型 benchmark 考试或师生模型蒸馏带来的误报；这会遗漏仅在正文提到教育的条目。分类与召回是规则匹配，可能遗漏同义词或误判，不能视为人工核验的完整目录。若候选达到处理上限，页面将标为部分结果。新增 `education-arxiv` 采集源使用教育相关标题与 AI 术语组合检索论文，按既有采集计划运行；已有语料之外的新内容需要等采集成功后出现。

## 数据源运行状态

- 中国光电：原 RSS 已失效，线上源已停用。旧版生成的公司占位记录不应被展示为新闻；重新启用前需要配置并验证真实来源。
- SEC 8-K：修复采集器并补种缺失的源记录。当前主机访问 SEC submissions 接口返回 HTTP 403，新补的源默认停用；须配置有效的 SEC 访问身份和可用出口，验证后再启用。已存在的源开关不被迁移覆盖。
- arXiv：新增专题源前已从当前主机验证查询可返回论文；采集计划、上游可用性及文章相关性仍需分别观察。

部署前应在隔离数据库验证迁移、采集和页面，确认当前生产基线与并发任务状态。专题不会因为部署本身而自动填充历史 SEC 数据。
